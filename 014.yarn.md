## Introduction to Yarn

Yarn is a fast, reliable, and secure dependency management tool for JavaScript projects. Created by Facebook (now Meta) in collaboration with Google, Exponent, and Tilde, Yarn was designed to address performance and security issues in npm while maintaining compatibility with the npm registry.

### Key Features:
- **Fast**: Parallel installation and caching for faster dependency resolution
- **Reliable**: Deterministic installs via lock files ensure consistency across environments
- **Secure**: Integrity checks and security auditing protect against malicious packages
- **Offline Support**: Works without internet connection once packages are cached
- **Workspaces**: Native monorepo support for managing multiple packages
- **Plug'n'Play**: Alternative installation strategy that eliminates node_modules

```bash
# Check if Yarn is installed
yarn --version

# Basic package installation
yarn add lodash

# Install development dependencies
yarn add --dev jest
```

## Lock Files and Dependency Resolution

### Understanding yarn.lock
The `yarn.lock` file ensures deterministic installs by locking exact versions of all dependencies and their sub-dependencies.

```yaml
# yarn.lock example
lodash@^4.17.21:
  version "4.17.21"
  resolved "https://registry.yarnpkg.com/lodash/-/lodash-4.17.21.tgz#679591c564c3bffaae8454cf0b3df370c3d6911c"
  integrity sha512-v2kDEe57lecTulaDIuNTPy3Ry4gLGJ6Z1O3vE1krgXZNrsQ+LFTGHVxVjcXPs17LhbZVGedAJv8XZ1tvj5FvSg==
```

### Dependency Resolution Process
1. **Parse package.json**: Read dependency requirements
2. **Resolve versions**: Find compatible versions based on semver ranges
3. **Flatten tree**: Create a flat dependency tree to avoid duplicates
4. **Generate lock file**: Record exact versions for reproducible installs
5. **Install packages**: Download and place packages in appropriate locations

### Lock File Best Practices
```bash
# Always commit lock files
git add yarn.lock
git commit -m "Update dependencies"

# Clean install from lock file
yarn install --frozen-lockfile

# Verify lock file integrity
yarn install --check-files
```

## Yarn Workspaces

Yarn Workspaces allow you to manage multiple packages within a single repository (monorepo), enabling code sharing and unified dependency management.

### Setting Up Workspaces

#### Root package.json
```json
{
  "name": "my-monorepo",
  "private": true,
  "workspaces": [
    "packages/*",
    "apps/*"
  ],
  "devDependencies": {
    "typescript": "^5.0.0",
    "jest": "^29.0.0"
  }
}
```

#### Directory Structure
```
my-monorepo/
├── package.json
├── yarn.lock
├── packages/
│   ├── shared-ui/
│   │   ├── package.json
│   │   └── src/
│   └── shared-utils/
│       ├── package.json
│       └── src/
└── apps/
    ├── web-app/
    │   ├── package.json
    │   └── src/
    └── mobile-app/
        ├── package.json
        └── src/
```

#### Workspace package.json
```json
{
  "name": "@myorg/shared-ui",
  "version": "1.0.0",
  "main": "dist/index.js",
  "dependencies": {
    "react": "^18.0.0"
  },
  "peerDependencies": {
    "react": "^18.0.0"
  }
}
```

### Workspace Commands
```bash
# List all workspaces
yarn workspaces list

# Run command in specific workspace
yarn workspace @myorg/shared-ui add lodash

# Run command in all workspaces
yarn workspaces foreach run build

# Install dependencies for all workspaces
yarn install

# Add dependency to specific workspace
yarn workspace web-app add express
```

### Inter-workspace Dependencies
```json
{
  "name": "web-app",
  "dependencies": {
    "@myorg/shared-ui": "workspace:*",
    "@myorg/shared-utils": "workspace:^1.0.0"
  }
}
```

## Yarn Modern (Berry) vs Classic

### Yarn Classic (1.x)
- Uses traditional node_modules structure
- Compatible with existing npm workflows
- Stable and widely adopted
- Limited modern features

### Yarn Modern (2.x, 3.x, 4.x - Berry)
- Plug'n'Play by default
- Better performance and disk usage
- Advanced workspace features
- Modern JavaScript features support

### Migration from Classic to Modern
```bash
# Check current version
yarn --version

# Set version to modern
yarn set version berry

# Or set specific version
yarn set version 4.3.1

# Update configuration
echo "nodeLinker: node-modules" >> .yarnrc.yml  # If PnP not desired
```

### Configuration Differences
```yaml
# .yarnrc.yml (Modern)
nodeLinker: "node-modules"  # or "pnp"
enableGlobalCache: true
enableTelemetry: false
logFilters:
  - code: YN0002
    level: discard
```

## Plug'n'Play (PnP)

Plug'n'Play is Yarn's alternative installation strategy that eliminates the node_modules directory and uses a single .pnp.cjs file to resolve dependencies.

### How PnP Works
1. **No node_modules**: Dependencies are stored in a global cache
2. **Resolution map**: .pnp.cjs file contains dependency resolution information
3. **Runtime resolution**: Node.js uses the PnP loader to resolve modules

### Enabling PnP
```yaml
# .yarnrc.yml
nodeLinker: "pnp"
```

### PnP Benefits
- **Faster installs**: No need to copy files to node_modules
- **Disk space efficiency**: Shared cache reduces duplication
- **Strict dependency resolution**: Prevents accessing undeclared dependencies
- **Faster startup**: No filesystem traversal for module resolution

### PnP Limitations
- **Tool compatibility**: Some tools may not support PnP
- **Learning curve**: Different from traditional Node.js resolution
- **Debugging complexity**: Error messages can be less intuitive

### Working with PnP
```bash
# Install dependencies with PnP
yarn install

# Run Node.js with PnP
yarn node script.js

# Generate SDK for editor support
yarn dlx @yarnpkg/sdks vscode
```

### PnP Configuration
```yaml
# .yarnrc.yml
pnpIgnorePatterns:
  - "packages/legacy-package/**"

pnpFallbackMode: "dependencies-only"
```

## Real Project Example: Building a Task Management System

Let's build a complete task management system to understand every Yarn concept through practical implementation.

### Project Overview
We'll create a monorepo with:
- Frontend (React app)
- Backend (Node.js API)
- Shared utilities library
- Documentation site

### Step 1: Project Setup and Initialization

```bash
# Create project directory
mkdir task-manager
cd task-manager

# Initialize with Yarn
yarn init -y
```

**What happened?**
- `yarn init` creates a `package.json` file
- This file contains project metadata and dependencies
- `-y` flag accepts all defaults

**Why use Yarn?**
- Faster package installation than npm
- Deterministic installs (same versions everywhere)
- Better security with integrity checks
- Workspaces for monorepo management

### Step 2: Configure Workspaces

```json
// package.json (root)
{
  "name": "task-manager",
  "private": true,
  "workspaces": [
    "apps/*",
    "packages/*"
  ],
  "scripts": {
    "dev": "yarn workspace frontend dev",
    "build": "yarn workspaces foreach run build",
    "test": "yarn workspaces foreach run test"
  }
}
```

**Workspaces Concept:**
- Allows multiple packages in one repository
- Shared dependencies to save disk space
- Cross-package linking without publishing

### Step 3: Create Workspace Structure

```bash
# Create directories
mkdir -p apps/frontend apps/backend packages/shared-utils packages/ui-components

# Initialize each workspace
cd apps/frontend && yarn init -y
cd ../backend && yarn init -y
cd ../../packages/shared-utils && yarn init -y
cd ../ui-components && yarn init -y
```

**Directory Structure:**
```
task-manager/
├── package.json (root workspace)
├── apps/
│   ├── frontend/
│   │   └── package.json
│   └── backend/
│       └── package.json
└── packages/
    ├── shared-utils/
    │   └── package.json
    └── ui-components/
        └── package.json
```

### Step 4: Install Dependencies

```bash
# From root directory
# Install React for frontend
yarn workspace frontend add react react-dom

# Install Express for backend
yarn workspace backend add express

# Install development tools globally
yarn add -D -W eslint prettier jest

# Install TypeScript for all workspaces
yarn workspaces foreach add -D typescript
```

**Dependency Management Concepts:**
- `yarn workspace <name> add` - Install to specific workspace
- `yarn add -D -W` - Install dev dependency to root workspace
- `yarn workspaces foreach` - Run command across all workspaces

### Step 5: Lock Files and Dependency Resolution

After running installations, you'll see:
```
task-manager/
├── yarn.lock (single lock file for entire monorepo)
├── node_modules/ (shared dependencies)
└── .yarn/
    └── cache/ (cached packages)
```

**Lock File Concept:**
- `yarn.lock` ensures everyone gets same dependency versions
- Contains exact versions and integrity hashes
- Must be committed to version control

### Step 6: Configure Yarn Modern Features

```yaml
# .yarnrc.yml
nodeLinker: node-modules
enableGlobalCache: true
enableInlineBuilds: true

plugins:
  - path: .yarn/plugins/@yarnpkg/plugin-workspace-tools.cjs
  - path: .yarn/plugins/@yarnpkg/plugin-interactive-tools.cjs
```

**Configuration Concepts:**
- `.yarnrc.yml` controls Yarn behavior
- `nodeLinker` chooses installation strategy
- `enableGlobalCache` shares cache across projects
- Plugins extend Yarn functionality

### Step 7: Build Shared Utilities Package

```javascript
// packages/shared-utils/src/index.js
export function validateEmail(email) {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
}

export function formatDate(date) {
  return new Date(date).toLocaleDateString();
}

export function generateId() {
  return Math.random().toString(36).substr(2, 9);
}
```

```json
// packages/shared-utils/package.json
{
  "name": "@task-manager/shared-utils",
  "version": "1.0.0",
  "main": "src/index.js",
  "scripts": {
    "test": "jest",
    "build": "echo 'Building shared utils'"
  }
}
```

**Internal Package Concept:**
- Packages can depend on each other
- Use scoped names (`@task-manager/`)
- Share code without publishing

### Step 8: Use Shared Package in Frontend

```bash
# Add internal dependency
yarn workspace frontend add @task-manager/shared-utils
```

```javascript
// apps/frontend/src/App.js
import React, { useState } from 'react';
import { validateEmail, generateId } from '@task-manager/shared-utils';

function App() {
  const [email, setEmail] = useState('');
  const [isValid, setIsValid] = useState(false);

  const handleEmailChange = (e) => {
    const value = e.target.value;
    setEmail(value);
    setIsValid(validateEmail(value));
  };

  return (
    <div>
      <h1>Task Manager</h1>
      <input 
        type="email" 
        value={email}
        onChange={handleEmailChange}
        placeholder="Enter your email"
      />
      <p>Email is {isValid ? 'valid' : 'invalid'}</p>
    </div>
  );
}

export default App;
```

**Cross-Package Dependencies:**
- Yarn automatically links internal packages
- Changes in shared-utils immediately available in frontend
- No need to publish or version during development
